# CHANGELOG-759 — à fusionner dans CHANGELOG.md

## 15 octobre 2026 — issue #759

Agent d'exécution choisissable par projet, sans changer le comportement actuel — suite du recensement #756 : au lieu d'une couche d'abstraction dédiée (écartée par #756 tant qu'un seul agent supplémentaire est visé), un dictionnaire `AGENTS_CONNUS` centralise, par agent, tout ce qui variait en dur sur « claude » dans `watcher.py`. Nouvelle clé `.conf` facultative `AGENT` (défaut `claude`) : absente ou valant `claude`, elle produit exactement la même commande, les mêmes options et les mêmes messages qu'avant cette issue.

- **`watcher.py`** — nouveau champ `Config.agent` (défaut `"claude"`), lu par `charger_config()` depuis la clé `AGENT` (`brut.get("AGENT") or AGENT_PAR_DEFAUT`, normalisée en minuscules) avec validation contre `AGENTS_CONNUS` (échec propre au démarrage si valeur inconnue, même style que les autres validations de `charger_config`).
- **`AGENTS_CONNUS`** (nouveau dictionnaire, une seule entrée `"claude"` pour l'instant) centralise par agent : le binaire, la fonction de construction de la commande par MODE (`_construire_cmd_claude`, extraite telle quelle depuis `lancer_claude`), la commande de sonde de pré-vol + ses signatures d'auth expirée + son message, le message d'erreur si le binaire est introuvable, et la clause « sous-agents » du gabarit de prompt (point 4 des Instructions, propre à l'outil Task/Agent de Claude Code).
- Quatre points de branchement rebranchés sur `AGENTS_CONNUS[CFG.agent]` : `lancer_claude` (construction de `cmd`, message `FileNotFoundError`, clause de prompt), `verifier_preflight_token` (commande de sonde + signatures + message), `_nettoyer_orphelin_verrou_perime` (reconnaissance du process orphelin par le **nom de l'agent configuré**, plus jamais littéralement `"claude"` — et surtout jamais déduit du nom du projet).
- **Inchangé volontairement** : `_nettoyer_arbre_claude` (cible déjà le PID/pgid, jamais le nom — confirmé par son propre commentaire, #247 point 4) ; le champ `claude_pgid=` du fichier verrou (détail de format interne, couvert par un test de non-régression qui l'écrit/le lit littéralement — le renommer en `agent_pgid=` n'apportait rien d'observable et cassait ce test sans raison) ; les messages de log purement cosmétiques mentionnant « claude »/« Claude Code » (ex. `[DRY-RUN] Claude Code serait lancé…`, `claude a échoué (code …)`) — les généraliser aurait alourdi le diff pour un gain nul tant qu'un seul agent existe.
- **Hors périmètre, non touché** : interface web (validation du champ MODELE, sélecteur de configuration) et calibration des TIMEOUT — aucune des deux ne bloque cette préparation de terrain, rien à signaler à ce stade. Le bootstrap de création CCW (`_traiter_creation_projet_ccw`, decision #554) n'invoque déjà jamais `claude` et reste hors scope.
- **`tests/test_verification_commentaire_237.py`** : ajout de `agent="claude"` au `Mock` tenant lieu de `CFG` dans le scénario 2 (bout-en-bout `traiter_issue`) — sans quoi `verifier_preflight_token` levait un `KeyError` sur l'attribut auto-généré par `Mock()`. Seul fixture de test affecté par l'ajout de ce champ (les autres passent par `watcher.Config(...)` ou `SimpleNamespace` sans jamais atteindre ce point, ou héritent du défaut `"claude"` de la dataclass).
- **Vérification de non-régression** : `python3 -m py_compile watcher.py` propre, puis les 64 fichiers `tests/test_*.py` du dépôt passés un par un — tous verts après le correctif ci-dessus (dont les tests touchant directement aux chemins modifiés : `test_orphelin_verrou_perime_322.py`, `test_lecture_active_327.py`, `test_nettoyage_arbre_247.py`, `test_verrou_refus_precoce_584.py`, `test_worktree_parallelisation_337.py`, `test_reprise_worktree_725.py`, `test_creation_bootstrap_ccw_556.py`).
