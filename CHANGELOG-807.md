## Issue #807 — Interface web : les messages de panne de connexion doivent disparaître seuls et ne plus s'empiler

Pendant une coupure réseau, l'onglet Résultats réessaie régulièrement de recharger la liste des issues et échoue à chaque fois : chaque échec posait un nouveau bandeau en haut de l'écran (« Résultats — échec de chargement… », « Résultats — décompte non rechargé… », état de GitHub injoignable). Ces bandeaux, de type erreur/avertissement, ne disparaissaient jamais seuls (issue #730, persistance volontaire pour les erreurs demandant une action) et l'anti-empilement (issue #635, clé = type + texte exact) ne les fusionnait jamais puisque la liste des projets en échec change à chaque tentative — ils s'accumulaient donc indéfiniment jusqu'à un clic manuel sur chaque croix, alors que le panneau « Messages » garde déjà tout l'historique.

- **`static/js/socle/toasts.js`** : deux options facultatives ajoutées à `toasts.erreur`/`toasts.avertissement` (3ᵉ argument `options`), sans aucun effet sur le comportement par défaut.
  - `options.duree` (ms) : impose une disparition automatique (la pause au survol reste active, comme pour info/succès) au lieu de la persistance par défaut. Nouvelle fonction pure `dureeEffective(type, dureeDemandee)` : retombe sur `dureeAffichage(type)` si absente/non numérique.
  - `options.cle` : clé de regroupement choisie par l'appelant, qui remplace celle calculée depuis le texte exact (`cleToast`) — un nouveau message avec la même clé REMPLACE le contenu du toast déjà affiché (pas de compteur « ×N », contrairement à la fusion par défaut de l'issue #635) et relance son compte à rebours. Nouvelle fonction pure `cleEffective(type, texte, texteSecours, compteurUnique, cleDemandee)`, et `contenuRemplacement(texteNouveau, compteurActuel, remplacer)` qui factorise la décision fusion-par-compteur (inchangée) vs remplacement (nouveau).
  - `toasts.avertissement` acceptait déjà `comptabilise` mais pas `options` (`erreur` le faisait déjà depuis #782) : signature alignée.
  - Commentaire d'en-tête et commentaire du clic-fermeture-immédiate mis à jour (celui-ci s'applique désormais aussi à une erreur/avertissement à durée explicite, pas seulement à info/succès).
- **`static/js/resultats.js`** : les deux messages concernés (« Résultats — échec de chargement… », type erreur ; « Résultats — décompte non rechargé… », type avertissement) utilisent désormais `{ duree: 10000, cle: '<clé propre à la source>' }` — `resultats-echec-chargement` et `resultats-decompte-non-recharge`.
- **`static/js/socle/panne_github.js`** : le message d'état de GitHub (`verifierEtAfficher`, erreur ou avertissement selon la gravité renvoyée par `/github-statut`) utilise `{ duree: 10000, cle: 'panne-github-statut' }`. Le message « GitHub est rétabli. » (type info, déjà auto-effaçable, émis une seule fois par transition) n'est pas concerné.
- **Persistance des autres erreurs/avertissements inchangée** : aucun autre site d'appel (`toasts.erreur`/`toasts.avertissement` dans `ccw.js`, `attente.js`, `panneau_lateral.js`, `resultats_coches.js`, `socle/api.js`, et le reste de `resultats.js`) n'a été touché — en particulier les erreurs à `texteSecours` (issues #782/#790/#791), qui restent persistantes avec leur zone de texte sélectionnable. Le journal du panneau « Messages » continue de recevoir tous les messages dans tous les cas (`journaliser()` appelée pour toute occurrence, avant toute logique de durée/clé).
- **Autres messages du même genre repérés, non traités (hors périmètre de l'issue)** : `socle/api.js` (`toasts.erreur(err.message)`, 3 sites, message réseau générique pouvant varier et se répéter pendant une coupure) ; `ccw.js:400/405`, `panneau_lateral.js:540/571/587` et `attente.js:239` (« Erreur réseau : » + détail variable) ; `resultats.js:866` (« Résultats — mise à jour impossible pour … », une issue précise, hors des 3 messages explicitement listés par l'issue). Signalés dans le rapport de clôture, aucun n'a été modifié.
- **Tests** (`static/js/tests/toasts.test.js`, 10 scénarios ajoutés) : `dureeEffective` (repli sur `dureeAffichage`, durée explicite prioritaire, persistance par défaut maintenue, valeur non numérique ignorée), `cleEffective` (repli sur `cleToast`, clé explicite prioritaire même si le texte change, deux clés explicites distinctes ne se mélangent pas), `contenuRemplacement` (fusion par compteur inchangée, remplacement sans compteur, remplacements successifs). Logique pure, testée sous Node sans DOM — comme le reste du fichier (le rendu DOM réel, lui, est vérifié manuellement, voir `VERIFICATIONS_MANUELLES.md`).
- **`VERIFICATIONS_MANUELLES.md`** : nouvel item sous « Résultats » couvrant la disparition automatique sans croix, l'absence d'empilement malgré un texte changeant, la pause au survol, la journalisation dans le panneau « Messages », et la non-régression de la persistance par défaut des autres erreurs/avertissements.
- **`configs/*.conf`** : aucun fichier touché (garde-fou respecté).

Suite JS (`node --test static/js/socle/tests/ static/js/tests/`) : 393 tests, 393 réussis, 0 échec (383 avant, 10 ajoutés). Suite Python complète (`tests/lancer_tous_les_tests.py`) : 82 fichiers exécutés, 82 réussis, 0 échec — identique à l'état avant modification (aucun fichier Python touché).
