## Issue #808 — onglet Résultats : la section « Fichiers modifiés » d'une issue Windows doit dire clairement que l'inventaire n'est pas disponible

Depuis l'issue #788, la case à cocher d'une issue copie, en plus du résultat, une section « Fichiers modifiés » construite depuis l'inventaire serveur (`/inventaire-commit`) des commits de l'issue — route qui interroge le dépôt de travail du ThinkPad. Pour une issue Windows (label `for-windows`), les commits n'existent que sur le PC fixe (worktree `C:\CCW\worktrees\…`) : le ThinkPad ne les connaît pas, et chaque commit faisait échouer la requête (« ⚠ Commit … : inventaire impossible — fatal: bad revision … »). Correct mais déroutant : ce n'est pas une anomalie, seulement un cas où l'inventaire est impossible par construction.

- **`static/js/app.js`** : nouvelle fonction `estIssuePourWindows(it)`, détection du label `for-windows` factorisée hors de `prefixeOSCible` (qui l'appelle désormais) pour être réutilisée sans duplication. `etatCommitsDeclares` reconnaît un quatrième état, `'windows'` : une issue `for-windows` y est classée quels que soient les commits indiqués (hashes, « aucun » ou ligne absente) — **prioritaire** sur `'hashes'`, `'aucun'` et `'absente'`. Les issues sans ce label gardent un comportement strictement inchangé.
- **`static/js/resultats_coches.js`** : `texteSectionFichiers` ajoute le cas `'windows'` — titre de section suivi d'une phrase neutre, sans symbole d'alerte, expliquant que l'inventaire n'est pas disponible depuis le ThinkPad pour une issue Windows (commits sur le PC fixe, dans le worktree indiqué par la ligne « Commits »), et renvoyant vers l'entrée de projet `_ccw` de l'outil de relecture. `sectionFichiersModifies` n'appelait déjà `inventaireCommits` (et donc la route `/inventaire-commit`) que pour l'etat `'hashes'` — comme l'etat `'windows'` ne vaut jamais `'hashes'`, aucune requête d'inventaire n'est faite pour une issue Windows, sans changement de code supplémentaire à ce point précis.
- **Boutons Diff/All et route `/inventaire-commit`** : non modifiés, conformément au périmètre de la tâche (voir « constaté mais non traité » ci-dessous).
- **Tests** : `static/js/tests/hashes_commit.test.js` (+4 scénarios) — etat `'windows'` avec hashes exploitables (priorité sur `'hashes'`), en lecture seule (« … aucun … », priorité sur `'aucun'`), sans ligne « Commits » du tout (priorité sur `'absente'`), et non-régression des trois etats existants pour une issue sans le label. `static/js/tests/resultats_coches.test.js` (+2 scénarios) — texte exact de `texteSectionFichiers('windows', …)`, avec et sans hashes, sans symbole `⚠`. `static/js/tests/resultats_coches_variantes.test.js` (+2 scénarios, chemin de production complet via `basculer`) — texte neutre copié par la case pour une issue Windows (avec et sans hashes), et `global.fetch` instrumenté pour faire échouer explicitement le test (assertion, pas d'exception avalée) si une requête `/inventaire-commit` est faite.
