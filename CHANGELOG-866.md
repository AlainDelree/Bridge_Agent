## 9 novembre 2026 — issue #866

§16 « Agent Windows CCW » : nouvelle sous-section 16.1 documentant le piège de routage des labels `for-linux`/`for-windows` sur un **poste Windows seul** (sans second poste CCW, agent Vibe ou Claude Code) — une issue labellisée `for-windows` sur un tel poste n'est traitée par aucun watcher local (chaque watcher filtre sur `LABEL` = `for-linux` par défaut dans son `.conf`) et le démarrage automatique de repli (`app/ccw.py::demarrer_service_ccw_arriere_plan`) échoue silencieusement : il tente un `nssm start` **local** sur un service CCW qui n'existe pas sur ce type de poste (#864 n'installe que des tâches de session, jamais un service NSSM) — seul le journal serveur en garde trace, jamais l'issue GitHub ni l'utilisateur. Nouveau document `provisioning/windows/ROUTAGE_LABELS_POSTE_SEUL.md`, repris par le futur guide d'installation. Solution de fond (réglage `MACHINE_SEULE` dans `identite_locale.conf`, #859, traitant les deux labels localement sans SSH) comparée à deux autres pistes puis **non implémentée** ici — trop de fichiers sensibles touchés (`watcher.py::lister_issues()`, `app/issues.py`, `scripts/watcher_issues_inbox.py` ×2, `app/interruption.py`), sans possibilité de test réel sous Windows depuis cet environnement : voir l'issue #867 (ouverte par #866) pour l'implémentation détaillée. Vérifié par lecture : `provisioning/windows/installer_demarrage_session.ps1` (#864) signale déjà clairement (avertissement visible) un projet sans `configs/<nom>.conf` — aucune correction nécessaire sur ce point.
