## 10 novembre 2026 — issue #870

Premier essai de l'installation « Windows seul » (compte de test sur le PC d'Alain, `COPIE_NON_PROPRIETAIRE` actif depuis #869) : après la création d'un projet depuis l'interface, trois éléments inadaptés à une copie de l'outil utilisée seule.

**1. Faux message d'échec de la doc — cause.** `nouveau_projet.creer_projet()`/`supprimer_projet.supprimer_projet()` ne tentent JAMAIS de commit/push sur `BRIDGE_AGENT_DOC.md` quand `COPIE_NON_PROPRIETAIRE` est actif (comportement voulu, #869) — mais renvoyaient alors `doc_commit_statut = None` (jamais calculé, puisque `committer_pousser_doc()` n'est pas appelé dans ce cas). Les deux consommateurs côté interface (`afficherRappelGit` dans `static/js/app.js`, `messageStatutCommitDoc` dans `static/js/config.js`) traitaient `None` comme n'importe quel statut inconnu : un échec supposé — affichant un encadré orange « Action requise — dépôt Bridge_Agent : committer/pousser la doc » (avec des commandes `git add`/`commit`/`push` et un chemin `~/Bridge_Agent`) ou un message affirmant « BRIDGE_AGENT_DOC.md a été committé et poussé automatiquement », alors qu'aucun commit n'a jamais été tenté. **Corrigé à la source** : `doc_commit_statut` vaut désormais explicitement `"non_applicable"` dans ce cas (jamais `None`), reconnu par les deux consommateurs — `afficherRappelGit` masque l'encadré comme pour `"ok"`/`"rien_a_faire"`, `messageStatutCommitDoc` renvoie une chaîne vide (l'étape « Documentation » du compte-rendu a déjà annoncé le fichier local écrit à la place).

**2. Encadré du hook de relecture (Relecture_Bridge, #578) — détection choisie.** Cet encadré (« Action requise — relancer le hook de relecture », `cd ~/Relecture_Bridge && ./installer.sh`) s'affichait SANS CONDITION après toute création de projet, alors que Relecture_Bridge est un outil propre à la machine d'Alain, absent par construction d'une copie tierce. Détection retenue, la plus simple après lecture du code : existence du fichier `~/Relecture_Bridge/installer.sh` (`identite.relecture_disponible()`, même pattern que `identite.copie_non_proprietaire()`/`identite.machine_seule()`). `creer_projet()` renvoie ce booléen (`relecture_disponible`) ; `static/js/app.js` n'affiche l'encadré que s'il est vrai — comportement strictement inchangé sur les machines d'Alain, où ce chemin existe réellement.

**3. Réglage `MACHINE_SEULE` — masquage d'interface, pas de routage.** Nom repris tel quel de la « solution de fond » déjà évoquée (non implémentée) au §16.1 de `BRIDGE_AGENT_DOC.md` et au §4 de `provisioning/windows/ROUTAGE_LABELS_POSTE_SEUL.md` (issue #866/#867), mais avec un périmètre volontairement plus étroit. Nouveau réglage facultatif dans `identite_locale.conf` (racine du dépôt, gitignoré, hors `configs/*.conf`, `identite.machine_seule()`, même convention de valeurs que `COPIE_NON_PROPRIETAIRE`/`MAJ_AUTO_DEPOT`) : **désactivé par défaut, comportement STRICTEMENT inchangé pour les installations d'Alain**. Une fois actif (lu par `app/vues.py::index()`, transmis au gabarit Jinja), masque l'onglet « CCW » de la barre d'onglets et la case « Projet CCW » du formulaire de nouveau projet (`templates/fragments/onglets.html` / `modale_nouveau_projet.html`, `display:none` CSS posé par Jinja — les deux éléments restent dans le DOM : `static/js/app.js` les référence par `getElementById` sans jamais vérifier leur existence à l'ouverture/fermeture de la modale ou au clic sur un onglet ; les en retirer casserait ces appels). **N'implémente PAS** le routage réel des labels `for-linux`/`for-windows` décrit dans ces deux documents (#867, toujours hors périmètre) — seulement le masquage de deux éléments d'interface sans aucune utilité et à risque d'erreur sur un poste seul (case « Projet CCW », qui échoue proprement par manque de second poste joignable).

**Autres éléments supposant la configuration d'Alain, repérés mais non corrigés (hors périmètre de cette issue, proposition de portée) :**
- `static/js/resultats_coches.js` (lignes ~263-266) : le message expliquant pourquoi l'inventaire des fichiers modifiés d'une issue CCW n'est pas disponible nomme littéralement « le ThinkPad » (« L'inventaire des fichiers modifiés n'est pas disponible depuis le ThinkPad pour une issue Windows… »). Sur une autre machine (y compris le PC fixe d'Alain lui-même, qui n'est pas le ThinkPad), ce texte se lirait de façon incongrue. Portée proposée : généraliser à « cette machine »/« le poste local », changement isolé d'une chaîne, sans toucher à la logique — `rapide`.
- `templates/fragments/onglet_config.html` (ligne ~38) : l'attribut `title` du champ « Tâches mode_write en parallèle » mentionne le modèle matériel réel du PC fixe d'Alain (« CCW (Pentium G2020 dual-core) ») comme justification du plafond. Trivia propre à sa machine, sans impact fonctionnel (juste une infobulle), mais à généraliser (« le poste CCW ») si l'onglet CCW devient pertinent pour d'autres configurations matérielles. Portée proposée : `rapide`, cosmétique.
- `templates/fragments/onglet_ccw.html` : son panneau reste dans le DOM même quand l'onglet est masqué par `MACHINE_SEULE` (seul l'onglet lui-même est masqué, pas son panneau) — inatteignable par la navigation normale (aucun onglet ne l'active), donc pas une fuite active, mais vérifié uniquement par lecture du code. Portée proposée : aucune action nécessaire sauf si un test manuel révèle un chemin d'accès direct (ex. ancre d'URL) — à surveiller lors de l'essai manuel sur la copie Windows seul.
- `static/js/config.js` (ligne ~176) : le repli `cd ~/Bridge_Agent && git push` de `messageStatutCommitDoc` (utilisé seulement si le serveur ne fournit aucune `commandeManuelle`) suppose ce chemin précis ; en pratique mort, `regenerer_tableaux_projets._commande_manuelle_doc()` fournit toujours une commande avec le vrai chemin pour les statuts `"echec"`/`"push_echoue"`. Portée proposée : aucune action, repli déjà inatteignable en pratique.
- Bandeau annuaire des jetons (`app/jetons_annuaire.py`, licence d'évaluation Windows CCW) : vérifié sans risque — lit un fichier séparé (`~/.config/annuairetoken/jetons.json`) absent par construction hors de la machine d'Alain, renvoie `None` dans ce cas (rien affiché). Pas d'action nécessaire.
