## 10 novembre 2026 — issue #874

Ajout de `provisioning/windows/installer_windows_seul.ps1` (issue #874) — automatise ce que `GUIDE_INSTALLATION_WINDOWS_SEUL.md` décrivait jusqu'ici à la main, sans droits d'administrateur, de façon relançable sans dommage (idempotent) et avec une simulation `-DryRun`.

**Ce que fait le script, dans l'ordre.** (1) Vérifie l'environnement : refuse PowerShell ISE et la fenêtre 32 bits sur un Windows 64 bits (détectée via `PROCESSOR_ARCHITEW6432`), signale clairement si `winget` est absent sans bloquer le reste. (2) Installe Git, GitHub CLI et Python via `winget` seulement s'ils manquent (détection par `winget list`, pas par `Get-Command` — contourne l'ambiguïté de l'alias Python du Microsoft Store), avec les options qui évitent la question sur la source « msstore ». (3) Rend le vrai Python utilisable dans la session en cours (recherche sous `$env:LOCALAPPDATA\Programs\Python`, ajout en tête de `$env:Path` pour cette fenêtre seulement) quand le raccourci du Store le masque, et explique comment désactiver les alias d'exécution sans jamais y toucher automatiquement. (4) Clone le dépôt dans `-Dossier` (défaut : `Bridge_Agent` dans le dossier personnel) ; refuse un dossier protégé (Program Files, Windows) ; un dépôt déjà présent n'est mis à jour qu'en avance rapide (`git pull --ff-only`), jamais écrasé. (5) Crée `identite_locale.conf` (ASCII, sans BOM) avec `COPIE_NON_PROPRIETAIRE`, `MAJ_AUTO_DEPOT` et `MACHINE_SEULE` à `oui` (issues #868/#869/#870), sans jamais écraser un fichier existant ; vérifie que git l'ignore et que `identite.py` le lit. (6) `-ProtegerPush` règle l'URL de push de `origin` sur une valeur invalide, pour qu'une copie ne puisse jamais pousser vers le dépôt d'origine. (7) Vérifie `gh auth status`, sans automatiser la connexion elle-même (interaction humaine requise). (8) Installe les dépendances de l'interface (`pip install -r requirements.txt`), sans pare-feu ni mode `--lan`. (9) `-AvecVibe` installe `uv` puis `mistral-vibe` dans la version figée du guide (`-VersionVibe`, défaut `3.1.0`, jamais « la dernière »), copie `bridge_ecriture.toml` ; la connexion par compte (`vibe --setup`) reste manuelle. (10) Pose un raccourci `bridge` (`bridge.cmd` + `bridge_lanceur.ps1` dans `$env:USERPROFILE\.local\bin`, ajouté au PATH utilisateur) plutôt qu'une fonction du profil PowerShell — qui ne se chargerait pas si la politique d'exécution par défaut bloque les scripts d'un compte neuf, politique que ce script ne modifie jamais. `bridge.cmd` invoque PowerShell avec `-ExecutionPolicy Bypass` pour ce seul appel ; le lanceur teste d'abord si l'interface répond déjà sur `127.0.0.1:5100` (tâches de démarrage de session déjà actives) avant de la relancer, pour éviter un conflit de port. `-RetirerRaccourciBridge` le retire proprement. (11) `-ProposerDemarrage` affiche, sans jamais l'exécuter, la commande de `installer_demarrage_session.ps1` prête à l'emploi. (12) Résumé final : fait / déjà en place / étapes manuelles restantes dans l'ordre (connexion GitHub, connexion Vibe, premier projet, démarrage de session).

**Guide mis à jour** (`GUIDE_INSTALLATION_WINDOWS_SEUL.md`) : §2 et §3 décrivent désormais l'option « un seul script », avec la commande qui télécharge ce seul fichier depuis le dépôt officiel et l'exécute pour la session en cours (sans jamais modifier la politique d'exécution de la machine), accompagnée du risque (exécution de code téléchargé) et de la vérification à faire avant de retirer `-DryRun` ; §5 renvoie désormais vers ce raccourci `bridge` à la place de l'ancien alias de profil PowerShell non essayé.

**Non testé sur un vrai Windows** (script PowerShell, relu uniquement sous Linux — voir le rapport de clôture de l'issue pour le détail point par point de ce qui est vérifié par relecture et ce qui reste à essayer).
