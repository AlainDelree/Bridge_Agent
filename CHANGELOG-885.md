## 12 novembre 2026 — issue #885

Vibe 3.1.0 a retiré l'agent intégré `plan`, utilisé jusqu'ici par `_construire_cmd_vibe` (`watcher.py`) pour TOUTE issue en `MODE = lecture` confiée à cet agent — une telle issue échouait en 7,8 secondes avec `Error: Agent 'plan' not found.`, classée `needs-human`.

**Cause établie par lecture du code source installé** (`mistral-vibe==3.1.0`, dans un environnement virtuel jetable sous `/tmp`, jamais dans une installation réelle) : `vibe.core.agents.models.BuiltinAgentName` ne liste plus que `ask`/`accept-edits`/`smart-approve`/`auto-approve`/`explore`/`lean` — pas `plan`. `REMOVED_BUILTIN_AGENTS = {"plan": "ask"}` ne remplace `plan` par `ask` QUE quand il est la valeur du `default_agent` de la config (`AgentManager._replace_removed_default_agent`), pas quand il est passé explicitement par `--agent plan`, ce que faisait `_construire_cmd_vibe` : `AgentManager._profile_for` lève alors `ValueError("Agent 'plan' not found.")`, le message observé en production. `ask` (seul agent restant qui refuse l'écriture par défaut) demande une approbation à chaque outil — inutilisable en session non interactive. Sur le ThinkPad d'Alain (Vibe 2.26.1), `plan` existe encore : le comportement n'y change pas.

**Correctif : profil personnalisé `provisioning/vibe/agents/bridge_lecture.toml`**, même mécanisme que `bridge_ecriture.toml` existant. Permissions retenues, établies par lecture de `vibe.core.tools.builtins.*.py` et de `vibe config schema` (3.1.0, aucun outil de listage de répertoire séparé — ni `glob`, ni `list_dir`, ni `ls` — grep en pointant sur un répertoire est le seul moyen trouvé d'énumérer des fichiers sans `bash`) :
- `enabled_tools = ["read_file", "grep"]` — liste BLANCHE explicite (pas seulement des permissions `"never"` par outil nommé) : un outil hors liste disparaît purement et simplement de ceux proposés au modèle, y compris un outil futur non repris ici. Décisif : plusieurs outils compagnons de `bash`/`git_bash`/`powershell` (`*_stdin`, `*_output`, `*_sessions`) ont par défaut la permission `always` — une liste `"never"` ciblant seulement `bash`/`write_file`/`edit` les aurait tous laissés passer.
- `[tools.read_file]`/`[tools.grep]` `permission = "always"` (déjà le défaut du code, déclaré explicitement par cohérence de lecture).
- `[tools.write_file]`/`[tools.edit]`/`[tools.bash]` `permission = "never"` (défense en profondeur, déjà exclus par `enabled_tools`).

**`_construire_cmd_vibe`** choisit `bridge_lecture` pour `MODE_LECTURE` SEULEMENT SI `~/.vibe/agents/bridge_lecture.toml` existe (vérifié à chaque appel, jamais mis en cache) ; sinon repli inchangé sur `plan` — comportement strictement identique à avant pour une installation Vibe 2.x. Si ni l'un ni l'autre n'est réellement disponible côté Vibe (3.x sans ce profil déployé), l'échec brut de Vibe reste possible, mais `AGENTS_CONNUS["vibe"]["causes_connues_echec_rapide"]` reconnaît désormais la signature `agent 'plan' not found` et affine le message de clôture (quel profil manque, comment le déployer) au lieu de laisser l'erreur brute seule.

**Provisioning Windows** : `installer_windows_seul.ps1` copie désormais TOUS les profils de `provisioning/vibe/agents/` (plus seulement `bridge_ecriture.toml`) vers `~/.vibe/agents/` — une installation déjà faite n'a qu'à le relancer (idempotent). `GUIDE_INSTALLATION_WINDOWS_SEUL.md` (§6, §10, §13) et `provisioning/vibe/README.md` (nouveau §1 bis) mis à jour. `provisioning/mistral/INSTRUCTIONS_MISTRAL_BRIDGE_AGENT.md` §4 : le mode `lecture` est présenté comme fonctionnant normalement avec Vibe (profil dédié), avec une note sur quand le préférer au mode `écriture`.

**Point relevé en passant, non corrigé (hors périmètre)** : `bridge_ecriture.toml` déclare `[tools.read]`, qui ne correspond à aucun outil réel de Vibe (le nom exact est `read_file`, `BaseTool.get_name()` dérivant le nom en snake_case du nom de la classe Python) — sans conséquence puisque cet outil est de toute façon `always` par défaut, mais à corriger si ce fichier est revu un jour.

**Tests** (`tests/test_profil_lecture_vibe_885.py`) : choix de `bridge_lecture` si le fichier existe (HOME redirigé vers un dossier temporaire) ; repli sur `plan` sinon (régression) ; `MODE_ECRITURE` inchangé (`bridge_ecriture`) dans les deux cas ; reconnaissance de la signature `Agent 'plan' not found.` avec un remède nommant explicitement le profil à déployer. `vibe` n'est jamais invoqué (pas de session réelle, facturée).

**Non vérifiable depuis l'environnement Linux de l'agent** : le comportement réel de Vibe sous Windows. Établi uniquement par lecture du code source de la version 3.1.0 (installée dans un environnement virtuel jetable pour cette seule vérification) et par les tests unitaires de ce dépôt. **À essayer par Alain** : déposer une issue en `MODE = lecture` qui demande de lister les fichiers d'un projet basculé sur Vibe, et vérifier que le rapport liste effectivement des fichiers (pas `Agent 'plan' not found.`, pas de blocage sur une demande d'approbation).
