## 16 novembre 2026 — issue #887

Nouveau bouton **📊 Avancement** sur une issue en cours dans l'interface web (`new_issue.py`) : estime l'état d'avancement d'une tâche `mode_write` sans ouvrir de terminal — commits faits depuis `master`, fichiers modifiés (lignes ajoutées/retirées, en distinguant déjà committé et non committé), et heure de la dernière activité. Mise à jour à la demande (clic) uniquement, jamais par sondage permanent, et strictement en lecture (aucune commande git qui modifie quoi que ce soit, aucun verrou pris, aucun effet sur le traitement en cours).

**Emplacement choisi** : le panneau latéral « Infrastructure » (onglet Résultats), zone *Actions* de l'issue sélectionnée — là où vivent déjà les actions contextuelles sur une issue (Interrompre, Fermer, notifications) — plutôt qu'un nouvel onglet dédié, puisque la fonctionnalité est scopée à UNE issue précise (l'onglet « Git » générique multi-projets de l'issue #569 avait justement été retiré à l'issue #573, jugé hors du rôle de `new_issue.py`).

**Backend — `watcher.py`** : refactor de `_trouver_worktree_reutilisable` (RELANCE, issue #725) pour en extraire `_candidats_worktree_issue(cfg, numero)` (identification pure par `git worktree list`, nom `<projet>-issue<numero>[-bis|-ter]` + branche attendue) et `_meilleur_candidat_worktree(candidats)` (départage par dernier commit). Nouvelle fonction `_trouver_worktree_pour_issue(cfg, numero)` : même identification, mais SANS le filtre « pas en cours de traitement » — le bouton Avancement doit justement retrouver le worktree d'une issue ACTUELLEMENT en cours (donc verrouillée), jamais le reprendre. `_trouver_worktree_reutilisable` garde exactement son comportement d'avant (vérifié par `tests/test_reprise_worktree_725.py`, toujours au vert).

**Backend — nouveau `app/avancement.py`**, route `GET /avancement/<projet>/<numero>?labels=...` : labels transmis par le front (déjà en cache côté JS, même esprit que `POST /interrompre`) plutôt que relus via `gh`, pour distinguer sans appel réseau GitHub supplémentaire les cas dégradés — `for-windows` (issue sur la machine CCW, non prise en charge dans cette étape, **aucune tentative SSH**), `mode_scratch` (lecture active, pas de worktree de projet), ni l'un ni l'autre (lecture seule) — d'un `mode_write` dont le worktree est réellement introuvable ou déjà nettoyé. Pour le cas nominal : commits via `git log <HEAD de REP_TRAVAIL>..HEAD` dans le worktree, fichiers committés via `git diff <base> HEAD --numstat/--name-status -z`, fichiers non committés via `git diff HEAD` (tracké) + `git status --porcelain` (non suivi, compté par simple lecture du fichier, jamais par une commande git qui toucherait l'index). Réutilise les parseurs déjà testés `_parser_numstat_z`/`_parser_name_status_z`/`_statut_libelle` de `app/issues.py` (issue #788). Dernière activité = max(dernier commit, mtime des fichiers modifiés non committés).

**Frontend** : bouton `📊 Avancement` dans `static/js/panneau_lateral.js` (visible dans les mêmes conditions que l'icône ⛔ Interrompre — issue ouverte, en cours, ni `done` ni `needs-human`), nouvelle modale `templates/fragments/modale_avancement.html` (incluse dans `index.html`), rendue entièrement en JS (`rendreCorpsAvancement`, pure, testée sous Node) — jamais côté serveur. CSS minimal ajouté à `static/css/modales.css` (`.modal-carte-large`, sections `.av-*`).
